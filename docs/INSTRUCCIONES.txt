PUENTE GMAIL → DASHBOARD LOCAL

El puente (work_dashboard_sync.py) ya forma parte del proyecto: lo arranca «Iniciar Anka.bat» junto con el dashboard
y lo reinicia solo si se cae. Para ejecutarlo a mano, en la terminal con .venv activo y desde la carpeta del proyecto:
python .\work_dashboard_sync.py --once
Para mantenerlo activo:
python .\work_dashboard_sync.py --seconds 60
El equipo y el proceso deben permanecer activos. Ctrl+C lo detiene.
Usa la autorización Google y DATA_DIR existentes. Nunca envía, elimina ni modifica borradores.
Los borradores anteriores sin bloque JSON no se importan. 0 actualizados no es un error.
No cambia la tarea de ChatGPT: copia `docs/PROMPT_WORK_ANKA.txt` en las instrucciones de una sola tarea activa.
No actives dos tareas que creen borradores para el mismo evento. Identifica primero la otra tarea.
No hay pruebas con tu cuenta Windows realizadas desde ChatGPT.

PRUEBA
1. Ejecutar --once: verifica cuenta, permisos y módulos.
2. Copiar `docs/PROMPT_WORK_ANKA.txt` en una sola tarea activa y usar un nuevo correo de prueba elegible.
3. Confirmar que el borrador tiene el bloque JSON dentro de la sección interna.
4. Ejecutar --once y comprobar Dashboard actualizado: <thread_id>.
5. Recargar dashboard y verificar actividades y preguntas.
6. Ejecutar --once de nuevo: debería mostrar 0 actualizados para el mismo contenido.
7. Dejar --seconds 60 activo para las siguientes solicitudes.

LIMITACIONES
Si el borrador se envía o elimina antes de importar, el proceso no lo encontrará.
JSON inválido o hilo incorrecto no se importa. Los errores no se marcan como procesados.
La base de datos y sus escrituras siguen usando dashboard_upsert existente.
El estado mostrado por sync_status_text sigue describiendo la automatización anterior;
este paquete no cambia ese indicador. El terminal confirma la sincronización real.
